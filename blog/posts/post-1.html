eDEX-UI started as a desktop application built on Electron — a full-screen sci-fi terminal interface with real system monitoring, a virtual keyboard, a 3D globe, and an xterm.js shell. The question we asked ourselves: can we strip away all the native parts and keep just the aesthetic?

What Makes eDEX-UI Look the Way It Does

Surprisingly, almost everything visual in eDEX-UI is plain DOM and CSS. There's no Canvas rendering (except the globe, which we dropped). The entire layout is flexbox. Colors are driven by CSS variables injected at runtime from JSON theme files. Even the sci-fi border style — those distinctive clipped corners — comes from a small CSS library called augmented-ui. 

/* augmented-ui in action */
section {
    --aug-border: 0.2vh;
    --aug-border-bg: rgb(170, 207, 209);
    --aug-inset: 5px;
}

This meant the conversion to a static web page was mostly about removing things rather than rewriting them. We removed the Electron IPC calls, the Node.js systeminformation backend, node-pty, and all the Electron-specific APIs. The CSS we mostly kept intact.

The Three-Column Layout

eDEX-UI uses three sections side by side: a left info panel (17%), the central terminal (65%), and a right info panel (17%). For the blog, this maps naturally to:

  • Left sidebar — author info, blog stats, tags, clock
  • Main content — post list or article body
  • Right sidebar — search, recent posts, categories, open windows

The original CSS uses position: absolute for the side panels because they need to sit precisely relative to the Electron window. In the blog we override that with normal flexbox flow so the layout scrolls and adapts to the browser viewport.

Theme System

Each eDEX-UI theme is a JSON file with RGB color values, font names, and terminal colors. We load the selected theme at boot and inject the values into :root as CSS custom properties. The entire UI re-colors instantly: 

async function loadTheme(name) {
    const t = await fetch(`themes/${name}.json`).then(r => r.json());
    const s = document.documentElement.style;
    s.setProperty('--color_r', t.colors.r);
    s.setProperty('--color_g', t.colors.g);
    s.setProperty('--color_b', t.colors.b);
    // ...
}

Boot Animation

The original app reveals panels with staggered 500ms intervals, each triggering a CSS fadeIn keyframe animation. We preserved this by controlling animation-play-state via JavaScript: 

// Stagger left and right panel items
for (let i = 0; i < maxLen; i++) {
    await delay(400);
    leftItems[i]?.style.setProperty('animation-play-state', 'running');
    rightItems[i]?.style.setProperty('animation-play-state', 'running');
}

The result is a blog that boots like a terminal application — panels materializing one by one out of the dark background, with the sci-fi aesthetic fully intact.
